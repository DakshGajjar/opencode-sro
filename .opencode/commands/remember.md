I want to keep this: <the thing the user wants remembered>

Decide what kind of thing it actually is, because the two are stored differently.

If it is a suspicion about how the target behaves, record it with `sro_record_hypothesis`.
All four fields are required, and the fourth is the one that matters: `expected_evidence` has
to be a result you could be wrong about. If the user describes the expectation after the
test has already run, it fits any outcome, and a record like that cannot fail — so record the
expectation they had *before* testing, and if they did not have one, say that the hypothesis
is untestable as stated and ask them what would distinguish the two outcomes.

If it is a fact about the engagement — a scope clarification, a program contact, a rate limit
the researcher mentioned — it is not a hypothesis. Put it in the engagement, not the evidence
store, so it constrains later work instead of sitting next to findings looking like one.

Either way, read it back before saving and confirm the wording with the user. A hypothesis
recorded in the wrong words will be tested against the wrong thing later.

Then say what would settle it, and what the next step is.
